# Implementation status

This is the current status ledger for Note. “Complete” means implemented and relevant tests/validation have passed; planned behavior and documentation alone do not qualify. See `PROJECT_SPEC.md` for the full requirements and `docs/DEVELOPMENT_PLAN.md` for dependency order.

## Project foundation

| Area | Status | Evidence / remaining work |
|---|---|---|
| Repository and build configuration | **Partial** | Git baseline is established. CMake/C++20/Qt 6.9.1 production shell builds on the current Windows host; Linux/macOS deployment and V1 release packaging remain. |
| Application shell | **Partial** | QApplication/QMainWindow integrates New/Open/Save/Save As/Close, native dialogs, document tabs, close prompts, and a per-document project-owned editing view. Lifecycle services, configuration, settings/themes, command registry, and full V1 validation remain. |
| Technology evaluation | **Partial** | Isolated project-owned widget and gap/piece buffer benchmarks are recorded in `docs/EDITOR_PROTOTYPE.md`. QScintilla was not measured; the low-end reference device and cross-platform validation remain outstanding. |
| Editor architecture decision | **Partial** | Project-owned viewport renderer is provisionally selected. The production buffer now uses an indexed implicit-treap piece table with newline indexes, but worst-case fragmentation, long-line and reference-device behavior remain. |
| Hardware targets and performance budgets | **Partial** | The development host is now characterized and startup, idle memory, 1/10/50 MiB async-open, and 1/10/50/100 MiB FileService measurements are recorded in `docs/PERFORMANCE.md`. Startup and idle memory miss the provisional values on this host. Values remain unconfirmed; the owner has not selected a reference device, and real-display, low-end, and cross-platform validation remain. |
| Phase 02 document foundation | **Partial** | Implementation includes production buffer/document ownership, ID-only tab order, lifecycle workflows, native dialogs, save/close prompts, encoding/line-ending handling, atomic persistence, chunked async open/reload, cancellation/progress, external-change monitoring, fingerprint-based save conflict protection, drag/drop opening, and external app/terminal launch. Focused regression tests cover external modifications, save conflict preservation, confirmed reload, and missing-file detection. The complete Windows Debug build and sequential CTest suite pass (9/9); the workflow test also passed 20 consecutive runs. Current-host Release benchmarks measure async opening but not progressive display. Reference-device and cross-platform validation, actual GUI key-to-paint/frame timing, and progressive content availability remain. Do not call Phase 02 verified or complete. |
| V1 release readiness | **Not started** | No agreed editor features, file handling, recovery, platform validation, performance verification, or release packaging are complete. |

## System status

| System | Status | Remaining work |
|---|---|---|
| 01 Application Core | **Partial** | The entry point owns the document workflow lifetime and launches the Main Window. Full lifecycle coordination, application-wide state, bootstrap configuration, and resource handling remain. |
| 02 User Interface | **Partial** | Main Window integrates per-document editor views with keyboard and mouse input, viewport rendering, tab switching, dirty presentation, and existing file workflows. The renderer supports configurable line numbers (absolute/relative), active-line highlighting, indentation guides, whitespace markers, matching identifier occurrences, and optional wrapping. Offscreen tests and a Release offscreen paint benchmark exist; persistent settings/theme integration, context menus, configurable commands/keybindings, accurate wrapped-row scrollbar proportions, real-display validation, and platform coverage remain. `DocumentPreview` remains in the build but is no longer the active editor surface. |
| 03 Editor Engine | **Partial** | Production UTF-8 piece-table buffer with indexed piece/newline metadata and focused tests exists in `src/editor/`. Cursor/selection managers own scalar-safe multiple cursor and selection state; the editing engine batches multi-cursor edits, handles mixed selection/deletion and targeted cursor insertion, and rejects ambiguous ranges before mutation. Undo/Redo records grouped atomic transactions and restores document, cursor, and selection state. `BracketManager` supports configurable pairing for parentheses, square/curly brackets, and quotes, nested bracket matching, closer skipping, paired deletion, and quote-after-word suppression. `EditorView` integrates Alt+Click cursor toggling, multi-cursor editing/selections, and matching feedback with the viewport renderer. Basic inherited indentation and four-space Tab insertion are present. Language-aware string/comment context, configurable indentation, syntax services, broader command/input behavior, cross-platform validation, and reference-device performance validation remain. |
| 04 Document Management | **Partial** | Production Document Model/Manager, ID-only tab ordering, application workflow, and Qt Core File Service support chunked background reads/reloads, progress/cancellation, UTF-8/BOM, BOM-marked UTF-16, mixed LF/CRLF/CR preservation, duplicate-path activation, Save As, atomic saves, SHA-256 disk fingerprints, conflict rejection and safe reload publication. Focused tests cover lifecycle, external changes, conflict preservation, reload identity, and missing files; the Windows Debug suite passes. Formal platform and reference-device large-file validation remain. |
| 05 Language System | **Not started** | Registry, data-driven detection/definitions, incremental highlighting, and cache remain. |
| 06 Customisation | **Not started** | Settings, themes, typography/layout preferences, persistence, theme editor, and keybindings remain. |
| 07 Command and Input | **Partial** | File actions use shared Qt `QAction` dispatch and standard shortcuts. `EditorView` handles essential text input, navigation, selection, clipboard, and undo/redo actions. The specified command registry/executor, configurable shortcut dispatcher, command palette, context menus, and broader input routing remain. |
| 08 Search | **Not started** | Active-document find/replace, options, bounded regex handling, and match navigation remain. |
| 09 Session and Recovery | **Not started** | Session restoration and separate, debounced recovery snapshots remain. |
| 10 Platform Integration | **Partial** | Native Qt Open/Save dialogs, Unicode path conversion, `QFileSystemWatcher` file/directory monitoring with refresh, dropped-file opening, and external-app/system-terminal launch are implemented behind platform-facing helpers. Windows build/smoke only; Linux/macOS behavior and native watcher reliability require validation. |

No system is marked **Complete** in this baseline.

## Revised V1 development sequence

The remaining work is organised into integrated packages:

1. **Commands, customisation and search** — Systems 06, 07 and 08.
2. **Session and recovery** — System 09 integrated with application lifecycle.
3. **Core completion and platform integration** — outstanding work in Systems 01–04 and 10.
4. **V1 integration, validation and final performance optimisation**.
5. **Windows packaging and release preparation**.

The Language System (Phase 05 and System 05) is deferred until after V1 and is **Not started** by policy, not by an omission in implementation.

It also fixed theme export, which wrote only 6 colours. Each has a regression test. | 07 Command and Input | **Partial** | A stable command registry/executor, Keybinding Manager, Shortcut Dispatcher, command palette and shared-action context menus are integrated with existing Qt actions. All V1 commands, now including Find Next/Previous, Next/Previous Tab and Indent/Outdent Lines, appear in menus, the palette (with shortcut and description) and Settings > Keybindings with user-facing names. Enabled states are predicate-driven: no-document, Undo/Redo history and two-tab conditions. The context menu has a fixed order with disabled items shown. Conflicting shortcuts are rejected and name the other command. Offscreen smoke tests cover these. Stabilisation added PageUp/PageDown and Ctrl+Home/Ctrl+End and fixed new-document focus (see System 03); palette open, filter, wrap-around selection and Enter are covered by offscreen tests. Native keyboard-only walkthroughs and screen-reader accessibility remain unverified. |
| 08 Search | **Partial** | Active-document find/replace UI, plain and regular-expression modes, case/whole-word options, match highlighting, Find Next/Previous commands and undoable individual/all replacement are implemented. Stabilisation (2026-11-23) fixed three defects, each with a regression test: searches of 10 MiB or more gave up at the 100 ms budget with no matches (each window copied the rest of the document); catastrophic regular expressions were reported as complete with no matches; and the panel searched synchronously, re-running after every Replace All replacement. The panel now searches in 10 ms slices, regex `^`/`$` are line anchors, and a PCRE2 backtracking-limit hit is reported as stopped. Remaining: one PCRE2 call is bounded only by PCRE2's default limit (up to ~70 ms measured), matches spanning a 64 KiB window cut are not found, and there is no manual check of the panel on a real display. |
| 09 Session and Recovery | **Partial** | Application startup restores saved path order, active tab and cursor offsets; inaccessible paths are skipped with a status message. Session state uses atomic JSON. Modified buffers are debounced and periodically snapshotted separately using atomic, checksummed recovery files, with segment streaming to avoid full-document copies during save. Startup detects an unclean prior run and offers recover-as-untitled, discard or later; original files are never replaced. Focused storage tests cover normal/abnormal runs, multiple and large documents, corruption/interruption, deferred and repeated recovery, and external changes to originals. Crash injection (2026-11-23, `note_crash_recovery_tests`): a child process running the real `MainWindow` is killed with `TerminateProcess` after typing unsaved text; the next start detects the unclean run, restores the session, offers recovery, and opens the text as untitled while the original stays unchanged. A child saving 4–6 MiB files in a loop is killed at random points 10 times per run; in 20 kills over two runs the file was always a complete old or new version. Known limit: a kill mid-write leaves `QSaveFile`'s temporary file (for example `name.txt.ezSjjh`) beside the original. Not tested: power loss and OS crash (no flush-to-disk guarantee beyond `QSaveFile`), full disks, network drives, and non-Windows platforms. |
| 10 Platform Integration | **Partial** | Native Qt Open/Save dialogs, Unicode path conversion, `QFileSystemWatcher` file/directory monitoring with refresh, dropped-file opening, and external-app/system-terminal launch are implemented behind platform-facing helpers. Launch adapters validate target paths and report failure; regression coverage verifies Unicode round-trips and invalid targets without launching external processes. Stabilisation (2026-11-23) fixed two Windows defects. `note.exe` was a console-subsystem program, so a console window opened beside it; it is now `WIN32_EXECUTABLE`, with a PE-header regression test. The `cmd.exe` terminal fallback (used when `wt.exe` is unavailable) ran hidden from a GUI process because Qt passes `CREATE_NO_WINDOW`; it now requests `CREATE_NEW_CONSOLE`. A probe confirmed the hidden and visible behaviour on this host. Not verified: native file dialogs, drag/drop from Explorer, the actual Open Externally and Open Terminal launches from Note, and watcher reliability on network drives. Linux/macOS are unvalidated. |

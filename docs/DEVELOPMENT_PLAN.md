# Development plan

This plan preserves the dependency order in section 9 of `PROJECT_SPEC.md`. The isolated architecture prototype is complete as a research milestone; it does not count as implementation of production editor features.

Phase 02 implementation and current-host verification are documented, but the milestone remains **Partial**. The Windows Debug build and CTest suite pass; measured startup and idle memory miss provisional targets on this development host, which is not an approved reference device. Phase 03 and the explicitly selected Phase 04 have implementation work in place, but this does not waive the remaining Phase 02 acceptance work.

1. **Foundation (complete as a prototype):** CMake/Qt application shell and isolated editor/buffer prototype. Provisional hardware profile, budgets and validation method are recorded in [`PERFORMANCE.md`](PERFORMANCE.md). Name the low-end reference device and validate the provisional structure there.
2. **Document foundation (implementation addressed; verification partial):** production text buffer, Document Model/Manager, ID-only Tab Manager, workflow, native dialogs, tab switching and close prompts, encoding/line-ending preservation, atomic File Service, chunked asynchronous open/reload, progress/cancellation, external modification watcher and fingerprint checks, safe conflict/reload flows, drag/drop, and external app/terminal launch are implemented. The Main Window uses per-document `EditorView`s over the document buffer; `DocumentPreview` remains only as a legacy component. Focused lifecycle, conflict, external-change, and reload tests pass in the Windows Debug suite. Release measurements cover current FileService open/Save As and async opening; the separate actual-app startup and idle-memory sample is also recorded in [`PERFORMANCE.md`](PERFORMANCE.md). Remaining work: owner-selected reference-device validation, cross-platform builds/behavior, real GUI latency and frame pacing, progressive partial-document usability, true cold-start measurement, and representative long-line/large-file thresholds. Software-constrained runs are supplementary only.
3. **Core editor:** drawing surface and minimal renderer; insertion/deletion, selection, undo/redo, indentation, pairing. Cursor navigation and multi-cursor state management, the framework-independent Selection Manager, Editing Engine, Undo/Redo Manager, project-owned Qt viewport renderer, and per-document Main Window editor views are implemented. Keyboard and mouse input cover essential editing, independent multi-cursor selections, Alt+Click cursor toggling, clipboard, undo/redo, configurable pair types, nested matching feedback, and basic indentation. Language-aware string/comment context, configurable indentation, broader command/input integration, and real-display/reference-device validation remain.
4. **Editor presentation (implemented; validation partial):** renderer configuration now supports absolute/relative line numbers, active-line highlighting, indentation guides, whitespace markers, matching identifier occurrences, and optional word wrapping. Offscreen tests and a Release viewport benchmark are in place. Persistent settings/themes, proportional scrollbar behavior for wrapped visual rows, very-long-line limits, real-display/reference-device measurements, and cross-platform validation remain.
5. **Language system:** data-driven language registry/detection, initial language definitions, incremental viewport-first highlighting.
6. **Customisation:** settings/theme ownership and storage, theme editor/live preview, typography/layout and configurable keybindings.
7. **Commands and search:** unified commands/input/shortcuts/palette and active-document find/replace.
8. **Session and recovery:** tab/session restoration and debounced, dirty-only recovery snapshots.
9. **Platform integration:** implementation is in place for drag/drop, external app/terminal launch, and external modification detection; validate behavior on Windows/Linux/macOS and address platform differences found.
10. **Phase 02 verification and tuning (partial):** Windows Debug full build and sequential CTest pass 9/9; the workflow regression test passed 20 consecutive runs. Current-host Release runs at 1/10/50/100 MiB, application startup and idle-memory measurements, historical timing investigation, and outstanding acceptance status are recorded in [`PERFORMANCE.md`](PERFORMANCE.md). Startup and idle memory miss provisional targets on this non-reference host, and the 50 MiB workflow does not provide progressively usable content. Remaining gate: select and validate the owner-approved reference device, confirm targets, measure true cold start/actual GUI keystroke latency/real-display scrolling, validate progressive opening and large/long-line behavior, and run cross-platform builds and lifecycle checks. This gate remains incomplete.

Do not add Appendix A items without explicit approval. Performance is measured during development, not deferred to the final phase.
